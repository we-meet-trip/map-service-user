# 출시 전 실행 계약

이 변경은 기존 V001–V018을 고치지 않고 V019–V025로 전진한다. 데이터/볼륨 초기화는 필요 없다.

- `TRAINING_CAPTURE_ENABLED=false`가 기본이다. 후보 신호, 편집 학습사본, 프로필 segment, 주변 장소 노출/클릭, 도착 학습기록, export를 만들지 않는다. 추천 완료/편집/일정 저장과 실제 주변 장소 조회는 유지한다. 재활성화는 학습 기능 재개 검토 후 별도 작업이다.
- V019 편집 영수증은 학습 사본이 아니다. `Idempotency-Key`를 job+account 범위로 묶으며 응답을 암호화한다. 같은 키와 같은 요청은 처음 수락한 응답, 다른 요청은 409다. 재시도 보장 기간은 `redis.draft-ttl-seconds`와 같고 만료 영수증은 정리한다. 이후 편집을 지난 결과로 되돌리지 않는다.
- 외부 추천 조회/편집/재추천/저장/교체는 소유자가 확인되어야 한다. 소유자 없는 옛 작업은 자동 귀속하지 않는다. 결과와 편집의 기준은 PostgreSQL이며, Redis 실패가 완료된 편집을 되돌리지 않는다.
- V020 새 접근 토큰의 `sid`는 refresh session family와 연결된다. 갱신·로그아웃은 사용자 행 잠금으로 직렬화한다. 재사용된 refresh는 그 세션의 후손까지 폐기한다. 모든 JWT 사용은 계정 존재와 해당 새 세션의 유효성을 확인한다. `sid` 없는 기존 접근 토큰은 기존 blacklist/만료 규칙을 따른다.
- V021은 참가했던 `(start_seq,end_seq]` 구간의 합집합만 조회한다. 나가기는 방의 seq 발급과 같은 잠금으로 경계를 확정한다. 나간 뒤 REST 목록/이력/읽음 상한과 WS 수신을 차단하고, 재입장은 부재 중 메시지를 허용하지 않는다.
- **V021에 기존 참가자가 있으면 migration을 중단한다.** 과거 재입장/이탈 경계는 이전 스키마에서 복원할 수 없다. 운영자는 기존 메시지와 외부 이력으로 정확한 구간 매핑을 검토한 별도 전진 migration을 준비해야 한다. `last_read_message_seq`로 추측하거나 행을 삭제해 통과시키면 안 된다.
- V023은 탈퇴 후 지연된 worker/stream/DLQ 이벤트가 개인 결과를 되살리지 못하도록 job UUID만 남긴다. 모든 재생 경로가 소진되었다는 증거 없이 이 표를 정리하지 않는다. Redis 초안 삭제는 커밋 후 시도하며 장애 시 기존 TTL이 최종 보존 상한이다. DB 접근은 즉시 거부한다.
- V024 탈퇴 시 소유 채팅방은 닫고 일정/소유자 연결과 제목을 제거한다. 본인 메시지와 개인 시스템 참조는 삭제하고, 다른 사람의 메시지는 보존한다. Room JSON의 `schedule_id`/`owner_id`는 null일 수 있다. 사용자 자신의 계정·일정 삭제는 실제 탈퇴 요청에서만 수행한다.
- V025 일정의 사용자 참조는 새 쓰기를 FK로 검사하여 탈퇴와 겹친 늦은 저장을 차단한다. `NOT VALID`는 기존 고아 행을 변경하지 않는다. 기존 행 검토 후 별도 `VALIDATE CONSTRAINT` migration을 준비해야 하며, 검증을 위해 기존 행을 임의 삭제하지 않는다.
- 정상 일정 삭제는 학습용 여행본문을 비우고 채팅 FK에 필요한 숨김 행만 남긴다. 학습 HOLD에서 기존 학습용 90일 tombstone sweeper는 비활성이다.
- 직접 고른 경로는 `optimize=false`가 기본이며 명시적 true만 최적화를 요청한다. 실제 장소 검증은 Agent/Hub가 담당한다. Nearby wire는 `loc`로 요청하고 `{loc:...}` 응답을 복호화한다.
- 최종 재측정 이동시간이 기존 방문 시작을 넘거나 활동 시간 안에 들어오지 않으면 경로 응답과 저장을 거부한다(502). 영업시간을 확인하지 않은 채 방문 시각을 임의로 밀지 않으며, 재추천이 필요하다. 방문 종료 시각이 전부 없는 옛 본문에는 체류 시간을 만들어 넣지 않는다.
- YOLO는 사용자 JWT와 `X-Internal-Token`으로 `POST /api/v1/vision/permit`을 호출한다. `{consume:false}`는 연결 검증, 추론 직전 `{consume:true}`는 UTC 일별 계정 한도 소비다. 응답은 `user_id/remaining/reset_at`; 소진 429, Redis 장애·미설정 503이다. `VISION_DAILY_LIMIT=60`은 GCP 검증 기본값이며 운영 정책은 별도 명시한다. `VISION_INTERNAL_TOKEN`은 BFF와 YOLO에 동일한 비밀값으로 공급한다.

검증은 H2 메모리 DB 또는 새로 생성한 격리 PostgreSQL/Redis에서 수행한다. 운영/공유 Redis로 전체 Spring 컨텍스트 시험을 실행하면 Stream consumer가 실행되므로 금지한다. V021 guard 및 FK/cascade, 동일 세션 동시 갱신, leave/send 경쟁은 격리 PostgreSQL에서 최종 확인한다.
